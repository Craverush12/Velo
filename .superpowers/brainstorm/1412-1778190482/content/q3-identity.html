How does the MCP know who you are?

The memory graph is the product's real value — personalization across sessions. This determines how identity flows from any AI surface into Velocity.

A

Config-time — set once, forget forever

When you add Velocity to Claude / Claude Code, you set a VELOCITY_USER_ID in the MCP server config. Every call is automatically scoped to that identity. Zero friction at call time.

Simplest UX. Right for a personal tool. One person, one config, one growing memory graph.

B

Call-time — pass user_id in every tool call

Each tool accepts a user_id parameter. The AI (Claude, Codex) includes it when calling the tool. You can switch context per call — useful for teams or multiple profiles.

More flexible, slightly more friction. AI must remember to pass it — not guaranteed.

C

Both — config default with call-time override

Config sets a default VELOCITY_USER_ID. Any tool call can optionally pass user_id to override — e.g., switching to a "work" vs "personal" profile mid-session.

Best of both. Feels seamless by default, stays flexible for power users.
