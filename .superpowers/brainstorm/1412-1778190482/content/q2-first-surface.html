Which surface do you ship to first?

Different surfaces need different MCP transports. Pick your day-one target — others follow the same server, just different connection config.

A

Claude Code (CLI) + Claude Desktop

Stdio transport. One mcpServers entry in your Claude config. You can call Velocity tools mid-conversation in the terminal. Rich inline card rendering via Claude's artifact system.

Fastest to connect. You're already in this environment. Zero auth needed for local.

B

Streamable HTTP (Claude + ChatGPT + any client)

HTTP/SSE transport on a local port. Any MCP-compatible client can connect — Claude Desktop, Claude.ai, future ChatGPT plugins, Cursor, Windsurf. One server, all surfaces.

Slightly more setup but unlocks everything. The FastAPI app you have can host this directly.

C

Both — stdio wrapper + HTTP fallback

Ship a thin stdio shim (velocity-mcp.py) that proxies to the running FastAPI. Claude Code users get stdio. HTTP users hit the FastAPI MCP endpoint. Same logic, two entry points.

Most flexible. One FastAPI backend, two connection modes. Small extra file.
