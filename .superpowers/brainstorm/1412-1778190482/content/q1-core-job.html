What is the core job of the Velocity MCP?

This determines the tool surface, the inline card shape, and what "connecting" means for each AI platform.

A

On-demand prompt enhancer

You explicitly call enhance_prompt when you want it. Returns the enhanced prompt + annotated segments as an inline card. You copy and use it. Like a power tool you reach for.

Simplest to build. Works everywhere MCP is supported. Closest to what ThinkVelocity already does.

B

Always-on context layer

Velocity runs silently in every conversation. It injects your memory graph (domains, preferences, persona) into the system context automatically — no explicit call needed.

Higher value but harder: requires system prompt injection support. Claude Code and Claude Desktop support this. ChatGPT does not natively.

C

Both — a toolkit

MCP server exposes multiple tools: enhance_prompt (on demand), get_my_context (inspect your memory), refine_prompt (post-clarification). The user decides which to call.

Most powerful. Still shippable fast since the FastAPI backend already handles all three flows.
